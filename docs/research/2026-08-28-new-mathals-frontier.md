# 3. FORMATION-LIFT-001

## 3.1 Origin

The SMASH research thread distinguishes:

```text
carriers + declared relations
  -> generated whole + formation receipt
  -> optional reification as a new carrier
```

The critical law is:

```text
CURRENTLY PRIMITIVE
!=
PRIMITIVE ANCESTRY
```

A generated whole may later participate as an ordinary carrier without erasing how it formed.

## 3.2 Mathal

Let:

```math
(A,B,\rho) \xrightarrow{SMASH} W
```

and then:

```math
K := REIFY(W).
```

A later formation may treat `K` as a carrier:

```math
K \xrightarrow{I} X'.
```

The candidate pressure question is whether formation history changes future reachability after visible state is matched.

Construct:

```math
surface(K_1)=surface(K_2)
```

while:

```math
formation(K_1) \neq formation(K_2).
```

Apply the same declared intervention `I`.

If:

```math
future(K_1) \neq future(K_2),
```

then formation contains predictive state for this experiment.

## 3.3 Dogram v0 lowering

No new operator required yet.

A synthetic lowering can use two `reach@1` specimens with:

```text
same surface metadata
same mutation
explicitly different internal graph state
```

and compare their query results with `delta@1`.

Dogram may report:

```text
same declared surface
same intervention
reachable futures differ
```

Dogram may not conclude:

```text
formation is globally causal
history is sufficient
SMASH is universal
```

## 3.4 Kill condition

Do not promote a new operator if all useful FORMATION-LIFT specimens remain cleanly expressible as compositions of `reach@1` + `delta@1`.

# 4. FORMATION-QUOTIENT-001

## 4.1 Origin

The PASSAGE ALEX formation work separates:

```text
exact receipt / formation carrier identity
```

from:

```text
substantive formation basis
```

A receipt carrier may change while its substantive formation basis remains equivalent. Conversely, the same payload may carry different lawful formation ancestry.

## 4.2 Mathal

Define an experimental equivalence relation:

```math
r_1 \sim_F r_2
\iff
basis(r_1)=basis(r_2).
```

Then:

```math
id(r_1) \neq id(r_2)
\not\Rightarrow
[r_1]_F \neq [r_2]_F
```

and:

```math
payload(r_1)=payload(r_2)
\not\Rightarrow
[r_1]_F=[r_2]_F.
```

Compact law:

> **Different carriers may represent the same formation class; identical payloads may inhabit different formation classes.**

## 4.3 Dogram v0 lowering

This is already expressible with `delta@1`.

Example ordered trace:

```text
PAYLOAD
FORMATION_BASIS
CARRIER_ID
```

Case A:

```text
payload        SAME
formation      SAME
carrier_id     DIFFERENT
```

Case B:

```text
payload        SAME
formation      DIFFERENT
carrier_id     DIFFERENT or SAME
```

The first meaningful difference can therefore be located without teaching Dogram what a formation means.

## 4.4 Hostile controls

```text
UUID noise only
serialization-order noise only
metadata label change only
substantive decoder change
substantive derivation-basis change
payload mutation with formation held fixed
```

## 4.5 Kill condition

No quotient operator is justified while equality/delta over explicit basis digests answers the tested question.

Do not build `quotient@1` merely because quotient notation is convenient.

# 5. INFORMATION-FIBER-001

## 5.1 Origin

The Thirteenth Cup pair transform uses:

```math
M =
\begin{bmatrix}
1&1&0\\
1&0&1\\
0&1&1
\end{bmatrix}
```

with:

```math
\det(M)=-2.
```

Therefore the same relation topology behaves differently under different declared arithmetic domains:

```text
characteristic zero -> invertible
F3                  -> invertible
F2                  -> singular
```

The important portable primitive is not the determinant itself.

It is collision structure.

## 5.2 Mathal

For a deterministic finite map:

```math
f:X\to Y,
```

define the fiber over `y`:

```math
f^{-1}(y)=\{x\in X:f(x)=y\}.
```

If:

```math
|f^{-1}(y)|>1,
```

multiple source states collapse onto the same output.

Candidate law:

> **Information loss in a finite deterministic transform is witnessed by nontrivial output fibers.**

Useful classifications:

```text
injective
surjective
bijective
collision-bearing
constant
partial / insufficient
```

And receipt values:

```text
source_count
image_count
fiber_sizes
max_fiber_size
collision_count
injective?
surjective?
bijective?
```

## 5.3 Why v0 is insufficient

`delta@1` compares two declared executions.

`rectangle@1` compares four declared cells.

Neither enumerates a finite domain and groups source states by output.

A user can manually precompute fibers and feed the summary to Dogram, but then Dogram is no longer performing the discriminator.

This is a genuine capability gap.

## 5.4 Candidate v1 operator

```text
fiber@1
```

Provisional role:

```text
finite declared domain
+ deterministic declared mapping table
-> image + fibers + information-character receipt
```

Prefer an explicit mapping table in the first version.

Do not start with executable callbacks or symbolic formulas.

Example input concept:

```json
{
  "domain": ["000", "001", "010", "011", "100", "101", "110", "111"],
  "mapping": {
    "000": "000",
    "001": "...",
    "111": "000"
  }
}
```

## 5.5 Hostile controls

1. permutation table -> every fiber size one;
2. constant map -> one maximal fiber;
3. binary pair transform -> known collisions;
4. ternary pair transform -> no collisions over full 27-state domain;
5. incomplete mapping -> `INSUFFICIENT_TO_TEST`;
6. duplicate source declaration -> `REFUSE`;
7. metadata changes only -> same result, changed supplied-specimen digest;
8. output labels reordered -> same canonical result.

## 5.6 Kill condition

Do not add `fiber@1` if realistic mathal work only needs a handful of pairwise comparisons.

The operator earns existence when at least one real frontier question requires domain-wide collision structure and manual precomputation would hide the discriminator outside the receipt.

The Thirteenth Cup finite-field specimen currently satisfies that motivation strongly enough for design consideration, not yet implementation approval.

# 6. REDUNDANCY-AS-WITNESS-001

## 6.1 Origin

For the Thirteenth Cup model:

```math
p=R+Y,
q=R+B,
r=Y+B,
C=R+Y+B.
```

Then:

```math
p+q+r=2C.
```

Over `F3`:

```math
p+q+r+C=0.
```

Thus `C` adds no new degree of freedom when it is derived from the primitive triple, yet it can act as a parity/check coordinate.

## 6.2 Mathal

> **A coordinate may contribute zero independent state dimension while contributing positive error-detection or reconstruction value.**

Non-collapse:

```text
DERIVABLE
!=
DISPENSABLE
```

This matters beyond coding theory.

Potential examples:

```text
formation digest
checksum
redundant witness receipt
parity coordinate
reconstructed summary carrier
cross-owner consistency witness
```

## 6.3 Dogram v0 lowering

No new operator yet.

Use `delta@1` to compare:

```text
valid relation set
vs
single-coordinate corruption
```

and `rectangle@1` where a redundant coordinate is present/absent crossed with corruption/no-corruption.

The question becomes:

```text
Does the extra derivable coordinate change detectability?
```

not:

```text
Does it increase dimensionality?
```

## 6.4 Kill condition

No `parity@1` or `witness@1` operator unless repeated real specimens demand a standardized calculation not already captured by explicit relations plus `delta`/`rectangle`.

# 7. DECODER-PROBE-001

## 7.1 Origin

Recent ALEX research separates passive decoding from active probing:

```text
passive decoder
  observes / re-expresses tested state

active probe
  supplies an input capable of altering tested trajectory
```

The architectural criterion is behavioral, not nominal.

Something called a decoder is only a lens while it leaves tested dynamics untouched.

## 7.2 Mathal

Passive form:

```math
D:X\to O.
```

Active form:

```math
P:X\to X'\to O.
```

Hostile test:

```math
X'=X
```

for passive decoding under the tested conditions.

If:

```math
X'\neq X,
```

then the operation participated in the state transition and its intervention receipt belongs in formation ancestry.

Non-collapse:

```text
READING STATE
!=
CHANGING STATE
```

## 7.3 Dogram v0 lowering

Already expressible.

### `delta@1`

Compare pre/post state under:

```text
no decoder
passive candidate decoder
active candidate probe
```

### `rectangle@1`

Cross:

```text
hidden world state × decoder/probe condition
```

and test whether adding the candidate device changes whether hidden state affects output.

## 7.4 Hostile controls

```text
post-hoc decoder
weak probe that produces no measurable delta
probe with different policy
nominal decoder that injects energy/input
one-lucky-split overclaiming
metadata-only decoder identity change
```

## 7.5 Kill condition

No new `probe@1` operator while `delta` and `rectangle` can calculate the relevant intervention effects.

# 8. EDGE-INTERIOR-001

## 8.1 Origin

PASSAGE-WORLD introduces the hostile specimen:

```text
TWO ROADS / ONE DOOR
```

Core law:

```text
same source
+ same destination
+ same payload
+ different attributable interior history
!=
same passage
```

The owning systems preserve the difference through receipts rather than through route identity alone.

## 8.2 Current Dogram gap

Dogram v0 deliberately stores a directed edge as:

```python
(source, target)
```

and refuses duplicate endpoint pairs.

Therefore this object cannot represent:

```text
A --road alpha--> B
A --road beta----> B
```

when the only relevant distinction is attributable road interior.

This is not a bug in v0. It is a newly discovered limit of the chosen graph abstraction.

## 8.3 Mathal

A passage is not merely endpoint adjacency.

Treat a tested passage receipt as an ordered attributable trace:

```text
entry
step_1
step_2
...
exit
```

or as a sequence of owner receipts:

```text
LOADOUT receipt
3rdi projection receipt
ALEX formation receipt
new occurrence receipt
LOADIN.STEAD route receipt
```

Then two traces may satisfy:

```text
source(T1) = source(T2)
destination(T1) = destination(T2)
payload(T1) = payload(T2)
```

while:

```text
interior(T1) != interior(T2).
```

Candidate law:

> **Endpoint equivalence does not collapse attributable passage interior.**

## 8.4 Why not just upgrade `DirectedGraph`

Do not immediately turn Dogram into a general attributed multigraph.

That would widen:

```text
reachability semantics
ablation semantics
mutation semantics
canonicalization
edge identity
path tie-breaking
```

for a discriminator that may be better represented as a trace rather than connectivity.

## 8.5 Candidate v1 operator

```text
trace@1
```

Provisional role:

```text
ordered attributable traces
-> compare endpoint equality, payload equality, and first interior difference
```

Potential result:

```text
same_endpoints
same_payload
same_interior
first_interior_difference
trace_lengths
```

No causal interpretation.

No route/admission interpretation.

No statement that two traces are historically real.

## 8.6 Hostile controls

1. exact same trace -> no difference;
2. UUID/receipt-carrier noise only -> optional ignored coordinate when explicitly declared non-substantive;
3. serialization-order noise -> no fabricated interior difference;
4. substantive projection change -> first difference located;
5. substantive decoder change -> first difference located;
6. same route but different formation ancestry -> preserved difference;
7. refused destination -> passage ancestry remains inspectable without claiming consequence;
8. same interior but different endpoint -> endpoint difference remains visible;
9. missing interior receipt -> `INSUFFICIENT_TO_TEST` rather than inventing equality.

## 8.7 Kill condition

Do not add `trace@1` if `delta@1` over an explicitly ordered trace object is already sufficient once a clean specimen shape is declared.

This is the most important hostile question before implementation:

> **Is `trace@1` mathematically new, or only a convenient adapter around `delta@1`?**

If it is only an adapter, keep it outside the operator floor.

# 9. FINITE-ORBIT-001

## 9.1 Origin

The Thirteenth Cup finite-field specimen feeds the pair transform back into itself.

Over `F3`, the declared transform satisfies:

```math
M^6=I.
```

That exposes a recursive question Dogram v0 does not currently answer directly.

## 9.2 Mathal

For a deterministic finite-state transform:

```math
x_{n+1}=T(x_n),
```

every orbit eventually enters a cycle.

Return:

```math
\mu = \text{transient length}
```

and:

```math
\lambda = \text{cycle period}.
```

Useful receipt:

```text
initial_state
visited_count
transient_length
cycle_length
cycle_entry
cycle_states
terminated_by_bound?
```

Candidate law:

> **A recursive MutatedMathal should be pressured by its orbit, not only by one application of its rule.**

## 9.3 Why v0 is insufficient

`reach@1` applies one graph mutation.

`delta@1` compares two states.

Neither repeatedly applies a declared finite mapping until repetition.

Manual iteration moves the discriminator outside Dogram's receipt.

## 9.4 Candidate v1 operator

```text
orbit@1
```

First version should accept an explicit deterministic transition table, not executable code.

Conceptual specimen:

```json
{
  "states": ["s0", "s1", "s2"],
  "transition": {
    "s0": "s1",
    "s1": "s2",
    "s2": "s1"
  },
  "initial_state": "s0"
}
```

Expected:

```text
mu = 1
lambda = 2
cycle = [s1, s2]
```

## 9.5 Hostile controls

1. fixed point -> `lambda=1`;
2. pure N-cycle -> `mu=0`, `lambda=N`;
3. tail into cycle -> nonzero `mu`;
4. malformed nondeterministic table -> `REFUSE`;
5. transition references unknown state -> `REFUSE`;
6. incomplete table -> `INSUFFICIENT_TO_TEST`;
7. metadata-only mutation -> no orbit change;
8. canonical state ordering does not alter orbit result.

## 9.6 Kill condition

Do not add `orbit@1` if the Collective's recursive specimens remain small enough that explicit hand-unrolled traces plus `delta@1` are sufficient.

It earns existence when recurrence itself is the discriminator and the complete cycle/transient receipt matters.

# 14. Promotion gates

A candidate operator may enter v1 design only if all are true:

1. at least one concrete MutatedMathal cannot be cleanly expressed with v0;
2. the missing calculation is mathematical rather than semantic;
3. manual preprocessing would hide the discriminator outside the Dogram receipt;
4. input/output types can be declared without importing domain ontology;
5. deterministic behavior can be tested offline;
6. hostile negative siblings are known;
7. the operator does not mint evidence, support, truth, authority, or causation;
8. existing operators cannot provide the same result by simple composition without loss of provenance.

Failure of any gate means:

```text
HOLD
```

not operator promotion.
